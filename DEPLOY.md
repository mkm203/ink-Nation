# Deploying Ink Nation

The app is a normal Node.js server: Express serves the API **and** the website. It stores
everything in one SQLite file plus an `uploads/` folder, so it does not need MySQL, a
database server, or a build step.

**Use a host that runs Node, such as Render.** Netlify can host static files only, so it
cannot run this app (there is no serverless/API split; see [Netlify](#netlify) below).

---

## Render (recommended)

`render.yaml` in this folder is a ready-to-use Blueprint. It creates a Node web service
with a **persistent disk** mounted at `/var/data`, and points the database and uploads there.

### 1. Push the code to GitHub

The folder to commit is **`inkster-app/`** (the one containing `package.json` and `server.js`).
`node_modules/`, `.env`, `data/` and most of `uploads/` are already ignored.

### 2. Create the Blueprint

1. Open <https://dashboard.render.com> and choose **New +** → **Blueprint**.
2. Connect the repository. Render reads `render.yaml`.
3. Click **Apply**. The first deploy starts; the schema and starter content are created
   automatically on the first boot.

> The Blueprint uses the **Starter** plan because persistent disks are not available on
> the free plan. Without a disk the database and photos are lost on every deploy/restart.

### 3. Fill in the environment variables

Render marks these as `sync: false`, so it asks for them (or you add them under
**Environment**). `JWT_SECRET` is generated for you.

| Key | What it is |
|---|---|
| `ADMIN_PASSWORD` | Password for `/admin/`. **Required** — empty disables the admin area. |
| `JWT_SECRET` | Signs the admin cookie. Generated by the Blueprint; keep it stable. |
| `APP_URL` | Public URL, e.g. `https://ink-nation.onrender.com`. Used in Stripe return links and admin emails. No trailing slash. |
| `ADMIN_EMAIL` | Where the studio's copies of booking and payment emails go. Falls back to the studio email in the admin area. |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `MAIL_FROM` | Email delivery. Leave empty to skip emails; bookings and payments still work. Gmail needs an app password. |
| `STRIPE_SECRET_KEY` | `sk_test_…` or `sk_live_…`. Leave empty to hide card payments. |
| `STRIPE_WEBHOOK_SECRET` | Signing secret of the Stripe webhook endpoint (below). |
| `SLOTS_PER_ARTIST_PER_DAY` | Sessions per artist per day. Default `2`. |

Durable paths, already set by the Blueprint — do not point them outside the disk:

```
DB_FILE=/var/data/inkster.db
UPLOAD_DIR=/var/data/uploads
```

`NODE_ENV=production` is also set. It makes the admin cookie `Secure`, which requires
HTTPS — Render provides it. Do not set it when testing on `http://localhost`.

#### If you created the service manually (not from the Blueprint)

The deploy log will show an ephemeral path such as
`/opt/render/project/src/data/inkster.db`, and `DB_FILE` / `UPLOAD_DIR` will be missing.
Fix it in the dashboard:

1. **Upgrade to a paid instance type.** Render disks are not available on free services.
2. Open the service → **Disk** → **Add Disk**:
   - Name: `ink-nation-data`
   - Mount path: `/var/data`
   - Size: `1 GB`
3. Open **Environment** and add:
   - `DB_FILE=/var/data/inkster.db`
   - `UPLOAD_DIR=/var/data/uploads`
   - `NODE_ENV=production`
   - `APP_URL=https://YOUR-APP.onrender.com`
4. Save. Render redeploys automatically.

After the deploy, the log must contain:

```
Database file: /var/data/inkster.db
Uploads folder: /var/data/uploads
```

If you still see `/opt/render/project/src/data/...`, the environment variables were not
saved on this service. Note that Render's dashboard never shows a "database" for SQLite:
it is just a file on the disk. `GET /api/health` returning `{"status":"ok","database":"connected"}`
confirms the connection.

#### Copying your local data to the Render disk

The disk starts empty, so the app seeds fresh content. To keep your imported content:

1. Add the disk and environment variables above and deploy once.
2. Set up SSH: Render **Account Settings → SSH Public Keys**, then copy the SSH command
   from the service's **Connect → SSH** tab. It looks like
   `ssh srv-xxxxx@ssh.YOUR_REGION.render.com`.
3. Upload the database and images (stop the service first, or restart right after):

```powershell
scp -s .\data\inkster.db  srv-xxxxx@ssh.YOUR_REGION.render.com:/var/data/inkster.db
scp -s -r .\uploads\*     srv-xxxxx@ssh.YOUR_REGION.render.com:/var/data/uploads/
```

4. Restart the service. The log should still show `/var/data/inkster.db`.

If `scp` is inconvenient, Render's Shell page has `magic-wormhole` pre-installed:
run `wormhole send /var/data/inkster.db` there and `wormhole receive` locally.
Do **not** commit the database or customer photos to a public GitHub repository.

### 4. Stripe webhook (only for card payments)

In the Stripe dashboard → **Developers** → **Webhooks** → **Add endpoint**:

- URL: `https://YOUR-APP.onrender.com/api/webhooks/stripe`
- Events: `checkout.session.completed` and `checkout.session.async_payment_succeeded`

Copy the signing secret (`whsec_…`) into `STRIPE_WEBHOOK_SECRET` and redeploy.
The success page also checks Stripe directly, but the webhook is what confirms payments
reliably when the customer closes the tab.

### 5. Sign in

Open `https://YOUR-APP.onrender.com/admin/` with `ADMIN_PASSWORD`. Add the real artists,
their gallery photos, reviews, prices, and the studio details.

`https://YOUR-APP.onrender.com/api/health` should return `{"status":"ok","database":"connected"}`.
Render uses it as the health check.

## Moving your existing data from MySQL/XAMPP

The switch to SQLite starts with starter content. To bring the real content across:

```powershell
# from inkster-app/
npm run db:init
npm install mysql2 --no-save --no-package-lock
npm run db:import
```

The script reads `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` and `DB_NAME` from `.env`,
copies every table into `data/inkster.db` (same ids, so bookings and orders stay linked),
and replaces the starter rows. Tables that do not exist in the old database are skipped.
Run it on your computer, then upload the resulting file to the host.

**Photos:** uploaded files are in `uploads/` and are referenced by URL (`/uploads/...`), not
stored in the database. Copy the whole `uploads/` folder, for example:

- Render dashboard → your service → **Shell**, then upload files, or
- copy them into the mounted disk with `scp`/SFTP; the app expects them in
  `/var/data/uploads`.

If you only import the database, existing image URLs will 404 until the files are copied.

### Backups

The database is a single file. Download `/var/data/inkster.db` (plus `-wal`/`-shm` if
present) and the uploads folder from the disk periodically. Restoring is the reverse:
put the files back, redeploy.

## Netlify

Netlify can serve the HTML/CSS/JS in `public/`, but **the site needs the Express API** for
bookings, reviews, prices, orders, payments, admin sign-in and uploads. SQLite also needs a
real disk. Netlify Functions are not set up for this.

So: host the whole app on Render (or another Node host with a disk). You can still put
Netlify in front as a CDN, but that requires splitting the frontend from the API and adding
CORS, which this project does not do. Pointing Netlify at the Render URL is not needed.

Other hosts that work: Railway, Fly.io, a VPS. Anywhere with Node 22.5+ and a persistent
volume. Set `DB_FILE` and `UPLOAD_DIR` to paths on that volume and give the service a public
HTTPS URL in `APP_URL`.

## Local development

No MySQL or XAMPP needed now.

```powershell
cd inkster-app
npm install
Copy-Item .env.example .env    # then edit ADMIN_PASSWORD and JWT_SECRET
npm run db:init                # creates data/inkster.db + starter content
npm run dev                    # http://localhost:3000 and /admin/
```

Reset everything by deleting `data/inkster.db` and running `npm run db:init` again.

Tests use their own file (`data/inkster-test.db`) and fake Stripe/Bitcoin servers:

```powershell
npm test
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Admin area returns 503 | `ADMIN_PASSWORD` is empty. Set it and redeploy. |
| Admin signs out on every restart | `JWT_SECRET` is missing or changes. Set one long random value. |
| Data resets after a deploy | `DB_FILE`/`UPLOAD_DIR` are not on the persistent disk, or the disk is not mounted. |
| `Cannot find module 'node:sqlite'` | Node is older than 22.5. Render: set `NODE_VERSION`/`.node-version`. |
| Card payment says unavailable | `STRIPE_SECRET_KEY` is empty or not `sk_test_`/`sk_live_`, or `APP_URL` is wrong. |
| Stripe payment stays unpaid | Webhook URL/secret wrong, or the app URL changed after the session was created. |
| No emails | SMTP values incomplete. The app logs one warning and continues. |
| Everything is 404 except the homepage | The API is mounted before the static files; make sure you deployed the whole app, not just `public/`. |
